- **An update from an old drone config no longer leaves maburd stopped.** `install.py` keeps the drone's own `mabur.toml` on an update. A config from before per-width TX power walls still has `radio.rate_walls_rel`, a key maburd no longer knows, so v0.12's maburd refused it (`config: radio.rate_walls_rel: unknown key`) and did not start. `install.py` now renames it to `radio.rate_walls_rel_20` (with no `_40` table, 40 MHz uses the same walls, as before), or drops it when a `_20` table is already there. The original stays in the backup. A drone stuck after a v0.12 install is repaired by running the v0.12.1 `install.py` again.

maburd, the drone config and the apps are the same as in v0.12; the APKs only carry the new version number. A v0.12 ground station and drone work with v0.12.1.

v0.12 notes: the link stays on its top rung (NACK residual rule), `VENC_MIN_IQP` 42, A-MPDU off by default, the 40 MHz receive-gain floor, the Quest menu panel.
